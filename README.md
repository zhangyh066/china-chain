# 链谱（ChainAtlas）

> 原名「中国供应链图谱」—— A 股上市公司的产业链知识图谱。

A 股上市公司的产业链知识图谱。**4,071 家公司**按 24 个申万一级行业铺开，
每个行业一组"产业链概览卡"，点进去看这个行业落在哪些环节上、有哪些公司。

**零框架、零依赖、零构建**——原生 ES module，浏览器直接跑。

---

## ⚠️ 数据口径（必读）

**三层数据，真假各不同，页面上逐层标了。**

| 层 | 内容 | 真假 | 来源 |
|---|---|---|---|
| 行情与财务 | 价格/涨跌幅/市值/市盈率TTM/毛利率/净利率/营收增速/EPS | **真实** | akshare · 东方财富，2026-09-22 |
| 行业与环节归属 | 24 个申万一级行业、199 个产业链环节 | **真实** | 申万宏源行业分类 + 公开概念板块归类（`pipeline/chain_concepts.py`，人工审核） |
| **上下游连线** | 每家公司最多 4 家上游 + 4 家下游 | **推断的模拟数据，未经核实** | `pipeline/fabricate_chains.py`（人写的行业步进表 + 环节归属推导） |
| 手工价值链 | 151 家公司的五列地图 | 手写（标注"手工梳理"） | 早期人工整理 |

**不构成任何投资依据。**

> ⚠️ **两个必须说清的语义边界**
>
> 1. **"同属一条产业链环节"不等于"谁给谁供货"。** "锂电池概念"里的公司确实在同一条链上，
>    但彼此未必有买卖关系。首页卡片上说的"条产业链"、公司页的"所属产业链环节"，
>    都是这个口径。
> 2. **上下游连线是编的。** 我没有真实的供应商/客户数据（见下），这些边是按
>    "共享环节 + 行业步进表"推出来的结构示意。公司页地图上方有一行醒目的提醒，
>    hero 和页脚也各写了一次。

### 为什么只有 4,071 家，不是全市场

全市场 5,918 家（东财行情口径），其中一大半跟产业链无关。四条判据依次收窄：

| 判据 | 剔除 | 说明 |
|---|---|---|
| 一、B2B 属性 | — | 最本质，但客户数据批量拿不到，本版未启用 |
| 二、产业链位置 | 653 | 剔金融/地产/纯服务 |
| 三、能否归入某个产业链环节 | 630 | 真正起作用的一条 |
| 四、图上有没有连接 | 46 | 剔真孤点 |

验证指标（合格线是自己定的）：**孤立点 0.0%**（<10% ✓）· **每家所属环节 4.6 个**（3–8 ✓）。
完整的筛选规则与实测数字见 `pipeline/筛选标准.md`。

### 上下游连线是怎么"编"的（以及为什么不随机编）

随机配对的产物是噪音——给金融读者看是一眼假。现在的做法是**按真实结构推**：

1. **`CHAIN_STEPS`**：53 条人写的行业步进关系，形如
   `("有色金属", "汽车", "铝合金件")`、`("基础化工", "纺织服饰", "化纤原料")`。
   每一步单独看都站得住。
2. **只连共享同一个环节的公司**，且两家的行业必须在步进表里对得上。
   所以是"锂电池这个环节里，材料商 → 电池厂"这种关系，不是随机配对。
3. **取该方向上市值最大的几家**，而不是抽样——规则能一句话说清，也符合"供应链向枢纽集中"。
4. **同一对公司只给一个方向**。步进表里 `机械设备→电子（半导体设备）` 和
   `电子→机械设备（工控元件）` 两条都成立，于是共享多个环节的两家会被算成
   "互为上下游"。实测宇树科技的上下游名单里曾同时出现工业富联/立讯精密/兆易创新——
   一眼就是错的。现在按"支持方向的共享环节数 → 环节的精确度"裁决，平手就放弃这条边。

跑完的实测数字：**4,057 家有上下游 / 26,625 条边 / 平均每家 6.6 条**，
方向冲突 **0** 例、互指上游 **0** 例。（这是可以脚本复核的，见 `_verify/`。）

> **接口留好了**：真数据一到，只要把 `data/chains.json` 换成真实抽取结果，
> 前端一行都不用改——它只认 `{u: [[环节索引, 代码, 角色]], d: [...]}` 这个结构。

### 真实的供应链关系（最难的一块，目前没做）

**"谁给谁供货"没有开源数据源。** A 股没有标准化的供应链披露，唯一可靠来源是
年报里"前五大供应商/客户"及其占比，散在几千份 PDF 里。两条现实路径：

1. **自己从年报抽**（免费）：巨潮资讯网可下载全部年报，用 OCR + 抽取流水线处理；
   抽出来的对手方很多不是上市公司，需要做"公司名 → 股票代码"匹配
2. **买整理好的学术数据集**：ACADCN / 马克数据网已把"只保留双方都是上市公司"的
   匹配做好（约 2 万条）；学校若买了 CSMAR 最省事（注意：CSMAR 仅供学术使用，**不能公开部署**）

> 这套筛选的另一半价值在于：**它同时也是一份"该去爬哪 4,071 家年报"的清单**。

## 跑起来

需要一个静态服务器（`file://` 下 ES module 会被 CORS 拦住）。

**最省事：双击 `serve.bat`**，然后浏览器打开 http://127.0.0.1:8123/
（会弹出一个黑窗口，浏览期间别关它；看完按 Ctrl+C 或直接关窗口即可。）

它背后跑的是 `serve.py`——一个自写的静态服务，**给每个响应都加上
`Cache-Control: no-store`**。

> ⚠️ **为什么必须这样**：`python -m http.server` 只发 `Last-Modified`、不发缓存指令，
> 浏览器会按"启发式"自己决定缓存多久——大致是"距上次修改时间的 10%"。
> 文件越久没改，它敢缓存的时间越长：一个昨天下午改过的 `app.js`，
> 今天上午打开会被浏览器缓存一个多小时，期间刷新根本不问服务器。
> 表现就是"改了代码、刷新、还是旧页面"，控制台一句报错都没有。

> ⚠️ **另外，这不是一个常驻服务**：它只是一个临时进程。电脑重启、或者关掉那个黑窗口之后，
> 页面就打不开了——**文件没丢，重新双击 `serve.bat` 即可**。

手动起也可以：

```bash
cd china-chain
python serve.py 8123
# 打开 http://127.0.0.1:8123/
```

**没有构建步骤**，改完源码刷新即可。

## 改数据

只改 `pipeline/dataset.py`，然后重跑管线：

```bash
cd china-chain/pipeline
../.venv/Scripts/python.exe fetch_real.py        # ① 行情/财务（4 次请求）
../.venv/Scripts/python.exe fetch_industries.py  # ② 申万一级行业（31 次请求）
../.venv/Scripts/python.exe fetch_concepts.py all # ③ 产业链概念（185 次请求）
../.venv/Scripts/python.exe select_companies.py   # ④ 跑三条判据 → 入图清单
../.venv/Scripts/python.exe build_chain.py        # ⑤ 组装 data/*.json
../.venv/Scripts/python.exe fabricate_chains.py  # ⑥ 推断上下游 → chains.json
```

①②③ 都有磁盘缓存，**只跑一次**，之后改口径不用重新联网。
想改筛选规则就编辑 `chain_concepts.py`，从第 ④ 步重跑；
想改上下游的推断逻辑就编辑 `fabricate_chains.py` 里的 `CHAIN_STEPS`，单独跑第 ⑥ 步。

管线会做这些事：

1. 校验代码格式、去重、禁止自环
2. 从 301 条直接关系**推导出两级上下游**（一级供应商的供应商 = 自己的二级供应商）
3. 每个二级节点记下 `via`（经由哪家一级公司），供画图时把线连到正确的一级分组
4. **优先使用真实财务**（`pipeline/real/fundamentals.json`，由 fetch_real.py 生成）；
   取不到的那几家退回模拟（固定种子，可复现），并逐条标注 `simulated: true/false`
5. **TTM 市盈率是真算的**：TTM净利润 = 上一年全年 + 今年中报 − 去年同期中报
   （业绩报表给的是累计口径，可以这么相减），PE(TTM) = 总市值 ÷ TTM净利润
6. 写出 `data/` 下的全部文件

改了 `dataset.py` 之后如果出现"孤立公司"（没有任何上下游），管线不会报错，页面也能跑，但那张图会很空。建议跑完检查一下：

```bash
python -c "import json;cs=json.load(open('../data/index.json',encoding='utf-8'))['companies'];print([c['name'] for c in cs if c['nodeCount']==0])"
```

## 页面

| 路由 | 页面 | 内容 |
|---|---|---|
| `#/` | 首页 | 打字机标题 → 四个总览数字 → **24 张行业概览卡**（公司数/环节数/市值/平均涨跌/环节分布/龙头）；搜索时改成结果列表 |
| `#/i/{行业}` | 行业页 | 该行业的四个数字 → **环节分布**（可点筛选）→ 全部公司（行业内搜索 + 板块筛选 + "再看 60 家"） |
| `#/c/{代码}` | 公司页 | 十个行情指标 + 所属产业链环节 + 同行业共享环节的公司 + **五列价值链地图**（手工梳理的 151 家优先，其余用推断的上下游） |
| `#/worldmap` | 全景图谱 | **24 个小圆饼**：扇形 = 该行业的产业链环节，扇形大小 = 落在这个环节上的公司数。**一张线都不画**（小图上画归属线会是几百条，糊成一团） |
| `#/m/{行业}` | 行业环图 | **一个行业单独一张大圆饼**：公司点是圆环上的点（大小=市值、颜色=涨跌），外圈弧段是环节并带名字；鼠标点上去才画线。中间留白显示读数 |
| `#/vision` | 我们的观点 | 读 `content/vision.md` 渲染（自带 40 行 markdown 解析器） |

兼容旧路由：`#/atlas` → 全景图谱。

**顶栏搜索（任何页面都能用）**：输入 → 下拉给候选，按"像不像"排序
（代码全中 > 名称全中 > 名称前缀 > 代码前缀 > 名称包含 > 行业）。
`↑` `↓` 选候选、`回车`跳转、鼠标点击跳转、`Esc` 清空，点页面别处自动收起。

**为什么图谱是"小圆饼 → 大圆饼"两级**：一张页面级的图放不下 4,000 个点和它们的归属线
（上一版试过：几百条线糊成一团，根本看不出哪个公司属于哪个行业）。
所以拆成两级 —— 小圆饼只回答"这个行业由哪些环节组成、多大规模"，**不画线**；
点进去的大圆饼只放一个行业，**线只在鼠标落到某个点上时才出现**，而且贴着圆周走。

首页的搜索除了公司名/代码/行业，**也认产业链环节**——搜"锂电池"会给出匹配的
环节芯片（点一下只看这个环节的公司）和这些环节里的公司。清空搜索框即回到行业总览。

首页早先是"把所有公司卡片铺开、按行业分组、每组折 12 家"。4,071 家摊在首页
又长又慢，改成行业概览卡之后，一屏能看到十几个行业的规模对比——
**要看公司就点进那个行业**。

## 复刻了参考站的哪些设计模式

这个项目是照着 `Fundamental — Cross-Border Supply Chain Tracker` 的设计模式做的，**不是抄代码**。沿用/改造的关键点：

**1. 构建期干重活，运行期只读 JSON**
所有推导（两级上下游展开、布局用的度数、真实行情与财务的合并）都在 `pipeline/build.py` 里做完。前端不做任何聚合和计算，只负责"读 JSON + 画图"——这是能保持零框架的根本原因。

**2. 数据按变化节奏切文件**
`index.json`（目录，慢变）、`{代码}.json`（结构，只在源数据改时重建）、`fundamentals.json`（行情，独立节奏）。合成一个文件的话，改一个股价就要重建 159 个文件。

**3. 每一层数据都可失败**
`fundamentals.json` 拉不到就返回空对象，卡片照常渲染、只是没有数字——不白屏、不报错。

**4. 手写 hash 路由 + 三个保护**
旧路由兼容、异步渲染的竞态保护（加载途中用户跳走就不渲染）、手动接管滚动恢复（`history.scrollRestoration = "manual"`）。

**5. 加载细线的工程化**
深度计数（boot 和 route 各持一个，嵌套不闪）+ 350ms 门闸（快速导航根本不显示）+ WAAPI 的 `.finished` 收尾（不用定时器，避免主线程忙时跟 CSS 过渡抢时序）。

**6. Canvas 用种子固定随机**
自己实现 mulberry32，种子写死。**每次刷新图长得一模一样**——图表一旦每次换位置，就失去"地图"的意义了。行业弧段按连接度数排序，让 hub 居中、连线更短。

**7. 主题不闪**
`index.html` 里内联一段脚本，在首屏绘制**之前**就把主色属性打到 `<html>` 上。

**8. 加语言零代码改动**
丢一个 `locales/xx.json` + 在 manifest 加一行即可。`t(key, fallback)` 双层兜底，缺词永远不炸。

**9. 一堆细节处理**
海报式 hero 的"消耗"与滚动锚定补偿、iOS 输入框聚焦不缩放、自选列表的收据式折起动画、空状态用字符网格生成 SVG 猫头鹰、"新"角标的生命周期管理、13 处 `prefers-reduced-motion`。

## 配色系统：投行风（纸与墨）

配色不是挑好看的色，是**先定语义、再算距离，最后验证对比度**。

### 三层语义，互不重叠

| 层 | 用什么颜色 | 固定还是可切 |
|---|---|---|
| 纸与墨 | 米白纸 `#F5F3EE` / 墨 `#14181D` | 固定 |
| 主色（链接、按钮、选中态） | 藏青 `#13375E`，可切松绿 / 石墨 | **可切** |
| 点睛金 | `#A8863F`（细线 `#E0D3B4`） | 固定 |
| 价格涨跌 | 涨红 `#AE2A1E` / 跌绿 `#0E6B4A` | 固定（A 股惯例） |
| 产业链方向 | 上游藏青蓝 `#1D4E7C` / 下游古铜 `#9C5A2C` | 固定 |
| 行业分类 | 11 色，见下 | 固定 |

**铁律：同一个颜色不能承担两件事。** 三套语义（涨跌 / 链条方向 / 行业分类）
在同一屏里出现时也不重叠——这一点是算出来的，不是靠自觉。

> **注**：「下游古铜色」指的是 `#9C5A2C` 这种**深棕铜**，只用在数据元素上
> （节点左边框、列色带、连接线），面积很小。
> 它和"把整个页面底色染成浅棕"是两回事——后者试过，见下面「试过但否掉的方案」。

### 试过但否掉的方案：浅色古铜底

一度把页面底从米白改成浅古铜（`#EAE1D0` → `#D9C9AB`），理由是"米白和卡片只差 5% 明度，
卡片浮不起来"。做法上没什么问题：与卡片落差确实拉到 55%，正文对比度 10.9:1（AAA），
次级 5.3:1，弱化文字也同步加深到 5.2:1。

**但观感上被否了**——大面积的浅棕在屏幕上读起来是"土黄/芥末黄"，不是古铜。
古铜的高级感来自**深、小面积、有金属质感**，一旦摊平成整页底色就只剩下"旧"。

留给自己的教训：**判断一个颜色方向靠不靠谱，要先看大面积的实拍效果，再谈精修。**
这次是先算了一整套对比度、调了三档深浅、写完文档，才第一次让用户看到——
方向错了的话，前面算得再准也是白算。

> 被否掉的对比度核算脚本保留在 `pipeline/bronze_check.py`，
> 它本身是个通用的 WCAG 对比度检查器，换成任何底色都能用。

### 11 个行业色是搜出来的，不是手挑的

`pipeline/palette_search.py` 在"低饱和 + 中间明度（L\* 33~64）"的约束空间里做爬山搜索，
目标函数同时要求三件事：

1. 两两色差尽量大（正常视觉 / 红色盲 / 绿色盲三种条件下都要）
2. 避开已经被占用的语义色（上游藏青、下游古铜）——否则会出现"一色两义"
3. 保持哑光感（惩罚过饱和与过亮）

实测结果（`pipeline/palette_check.py` 可复跑）：

| 指标 | 参考站原配色 | 本项目 |
|---|---|---|
| 正常视觉最小色差 | ΔE 22.6 | **ΔE 26.1** |
| 红色盲最小色差 | ΔE 9.2 | **ΔE 10.6** |
| 绿色盲最小色差 | ΔE 18.0 | ΔE 13.1 |
| 与链条墨色的最小距离 | — | **ΔE 16.0**（无冲突） |
| 环上相邻行业最小色相差 | — | **50.1°**（扇区边界不糊） |

> 色盲模拟用的是 Viénot 型 LMS 线性变换，色差用 CIE76。这些是近似值，
> 够用于"能不能区分"的判断，但不是严格的色度学研究。

### 那些让版面"像报告而不像应用"的细节

配色只解决一半问题，剩下的一半在版式上：

- **圆角从 12px 收到 6px** —— "报告"和"网页应用"最容易分辨的一处
- **层次靠细线和留白，不靠投影** —— 投影只留了一层几乎看不见的"贴纸"实感
- **数字一律等宽对齐**（`font-variant-numeric: tabular-nums`）—— 报告里的数字列之所以齐，就靠这个
- **金色细线做栏目分隔**（顶栏上沿、每个区块标题上方）—— 报告的版面语言
- **卡片 hover 不再"往上飘"** —— 那是应用的动作；报告里只变边框
- **Canvas 直接读 CSS 变量取墨色** —— 否则 JS 里抄一份色值，总有一天两边会不一致
- **换底色必须回头检查"没有底板"的容器** —— 价值链地图原来没有自己的背景，
  底一深就露出古铜板，像"漏了个洞"。凡是靠底色的容器，换底时都要过一遍
- **本地开发服务器必须发 `Cache-Control: no-store`** —— `python -m http.server` 不发，
  浏览器按启发式缓存，改完代码刷新还是旧页面且零报错（见上方的 `serve.py`）
- **验证交互时别只依赖"关缓存的测试器"** —— 那会把缓存问题掩盖掉；
  另用 `_verify/cache-test.mjs` 在**缓存开着**的条件下复测一遍

开发过程中被这套测试抓出并修掉的真问题：

1. **五列被 flex 压扁**（`.vcm-col` 默认可收缩）→ 加 `flex: none`
2. **价格与市值不自洽**（宁德时代市值 1.05 万亿、股价 53.68 元）→ 改成"先定市值，再按总股本反推股价"
3. **市值抽样失真**（海天味业被随机成 1.8 万亿）→ 改用对数均匀抽样，中位数落到 729 亿
4. **hero 还原按钮失效**：还原动作本身发出的 scroll 事件把刚恢复的 hero 又判成"已滚过" → 判据从 scroll 监听换成 `IntersectionObserver`
5. **地图顶部空出 157px 且底部溢出**：缩放挂在 stage 上但 `transform-origin` 设在了外层 `.map`，导致按中心缩放 → origin 改到 stage 上
6. **二级连接线被卡片挡住**：线画到锚点会横穿一级列、且 z-index 在卡片之下 → 改为连到自己的一级父分组（数据里加 `via` 字段）
7. **图谱图例变成一排黑药丸**：`aria-pressed="true"`（表示"可见"）撞上了"实色填充"的样式语义 → 拆成"可见=浅色 / 已筛掉=压暗"，开关类控件单独用 ID 选择器
8. **行业色与下游古铜撞色**：「机械设备」的行业色与产业链的"下游古铜"色差只有 ΔE 6.7，在 Atlas 同一张画布上就是"一个颜色表示两件事" → 把"避开已占用语义色"写进配色搜索的目标函数
9. **环的首尾撞色**：铺排只优化了前 10 个位置，环形首尾相接处两个行业的色相几乎相同 → 把起点也纳入优化，相邻最小色相差 0°→50.1°
10. **价值链地图"漏底"**：`.map` 没有自己的背景，换深底色后左右留白直接露出页面底色 → 补上纸板底板
11. **图注配色文案与实现不一致**：配色从青/陶土换成藏青/古铜后，图注还写着"青色"
12. **`loadGraph()` 只存了 promise、没存结果** → 公司页的"所属环节/同行"永远空白。**页面看起来完全正常，只是没内容**，最难发现的一类
13. **"查看全部 N 家"点了没反应**：事件绑在工具栏上，按钮却在列表里 → 改绑 `document`
14. **3,749 家公司各产生一次 404**：非手工公司不该去请求卡片文件 → 用 `index.json` 的 `curated` 标记先判断
15. **口径文案里的 `<b>` 被转义成字面标签**：页面上真的显示字面的 `<b>` → 加 `richNote()`（先全转义、只把 `<b>` 放回来）
16. **价值链地图锚点显示 `sector.undefined`**：卡片里的字段叫 `industry`，地图节点要的是 `sector` → 加载时归一
17. **同一家公司同时出现在上游和下游**：步进表里两个方向都成立，共享多个环节的两家就被算成了互指 → 加方向裁决（证据数 → 环节精确度 → 平手放弃）
18. **顶栏搜索只有过滤、没有跳转**：在搜索框里打完整公司名，既没有候选也不跳转，而且过滤结果渲染在首屏之下，屏幕上毫无变化，看起来就像坏了 → 改为"输入给候选、回车/点击直接进公司页"；同时去掉"在别的页面打字会把用户强行拽回首页"的旧行为

## 已知限制

- **上下游连线是推断的模拟数据，不要当事实用**（口径见开头）
- 4,071 家是筛过的，不是全 A 股；14 家（0.3%）在现有步进表下推不出任何上下游
- 公司页在"原始尺寸"模式下需要横向平移看完整链条；地图高度随分组数量增长（宁德时代约 1450px）
- 无路由懒加载（六个页面共享同一个 `app.js`），无单元测试（只有端到端测试）
- 环图上线 300 家以上的行业会分 3 圈画（一圈挤不下 500 个点）；手机（<520px）只画市值前 90 家，完整名单在列表页
- 字符串拼 HTML + `innerHTML`，安全全靠一道 `esc()`——加新模板时**必须**继续用它
- 数据说明里带 `<b>` 的话，渲染处要用 `richNote()` 而不是 `esc()`（否则页面上会显示字面标签）
