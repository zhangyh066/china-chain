## 上下游连线推断方法

随机配对产生的是噪音。当前做法按真实结构推导：

1. **`CHAIN_STEPS` 行业步进表**：53 条人工编写的行业间步进关系，形如
   `("有色金属", "汽车", "铝合金件")`、`("基础化工", "纺织服饰", "化纤原料")`，
   每一条单独看都成立。
2. **只连共享同一环节的公司**，且两家行业必须在步进表中匹配。
   即"锂电池环节内，材料商 → 电池厂"这类关系，而非随机配对。
3. **每个方向取市值最大的若干家**，而非抽样——规则可一句话说清，也符合
   "供应链向枢纽集中"的经验规律。
4. **同一对公司只保留一个方向**。步进表中 `机械设备→电子` 与 `电子→机械设备`
   可能同时成立，共享多环节的两家公司会被算成"互为上下游"（实测曾出现
   同一家公司同时出现在对方的上下游名单中）。裁决规则：
   支持方向的共享环节数 → 环节精确度 → 平手则放弃该边。

实测结果：**4,057 家有上下游 / 26,625 条边 / 平均每家 6.6 条**，
方向冲突 0 例、互指上游 0 例。

> **接口已预留**：获得真实数据后，只需将 `data/chains.json` 替换为真实抽取结果，
> 前端无需改动——它只认 `{u: [[环节索引, 代码, 角色]], d: [...]}` 结构。

## 真实供应链数据

**"谁给谁供货"没有开源数据源。** A 股无标准化的供应链披露，唯一可靠来源是
年报中的"前五大供应商/客户"及占比，散落于数千份 PDF。两条现实路径：

1. **自行从年报抽取**（免费）：巨潮资讯网可下载全部年报，经 OCR + 信息抽取流水线处理；
   抽取出的对手方多数不是上市公司，需要额外做"公司名 → 股票代码"匹配。
2. **购买整理好的学术数据集**：ACADCN / 马克数据网已做好"双方均为上市公司"的
   匹配（约 2 万条）；若所在机构采购了 CSMAR 则更省事
   （注意：CSMAR 仅限学术使用，**不可用于公开部署**）。

这套筛选的另一半价值：它同时是**"应该去爬哪 4,071 家年报"的清单**。
